# Claude 封号风险检测

你的账号被封，可能不是养号的问题，是网络环境在裸奔。

一条命令，五项检查，两分钟出结论。不用懂技术。

## 它是什么

一个 AI Agent 的 Skill，也是一个能独立跑的脚本。

跑完给你三样东西：

1. **原始数据** — 每一项测出来的实际值
2. **判定结论** — 干净 / 有风险 / 已泄露
3. **人话解释** — 告诉你到底哪里有问题，怎么改

看不懂技术字段？报告最后有一段话，连同 JSON 一起贴给任意 AI，它会翻译。

## 为什么会有这个东西

浏览器有个功能叫 WebRTC，视频通信用。为了建立点对点连接，它会收集你本机所有网卡的地址，发给 STUN 服务器问「外面看我是什么地址」。

这一步走 UDP。

大部分代理只接管 TCP。于是同一个页面，网页请求报的是节点地址，WebRTC 报的是你家宽带地址。

网站两边一比，就知道你在哪。

还有第二条路：IPv6。TUN 只接管 IPv4 时，IPv6 从真实网卡直连。网卡上那些 `240e` 开头的地址，就是这条路。

以及第三条：分流规则判错，某些域名走了直连。

## 怎么用

不用装任何依赖，Python 3.8 以上就行。

```bash
python scripts/audit.py
```

它会自己打开浏览器做 WebRTC 检测，测完自动关页，然后生成报告。

常用参数：

```bash
python scripts/audit.py --no-browser     # 只查系统层
python scripts/audit.py --out ./结果      # 指定输出目录
```

退出码：`0` 干净，`1` 有问题或待确认。

## 它查什么

| 检查项 | 看什么 | 不合格意味着 |
| --- | --- | --- |
| 出口一致性 | 三个独立服务返回的 IP 是否相同 | 有流量绕过了代理 |
| WebRTC 反射地址 | STUN 看到的出口 vs 网页出口 | UDP 没走代理，真实 IP 暴露 |
| WebRTC 主机地址 | 有没有真实网卡地址 | 浏览器没做地址混淆 |
| IPv6 出网 | IPv6 能不能直连出去 | 多了一条不经代理的通道 |
| DNS 接管 | 解析是否走 fake-ip | DNS 明文直连，位置暴露 |
| TUN 与系统代理 | 代理到底有没有生效 | 后面几项都不用看了 |

## 输出长什么样

报告目录下生成两个文件：

- `report.json` — 完整结构化数据
- `report.md` — 三段式报告：数据 → 判定 → 人话

```
## 二、判定

**总体结论：CLEAN**（干净）

## 三、结论解读

没查到你泄露真实地址。网页请求和 WebRTC 报的是同一个出口，
本机内网地址和 IPv6 都没有露出去。

具体的判断依据有三条：

1. 网页请求和 WebRTC 报的是同一个地址，说明 STUN 也被代理接管了。
2. 浏览器只报出 2 条随机主机名，没有出现你的内网地址。
3. IPv6 这条路不通，或者被 DNS 层挡掉了。
```

## 它不保证什么

说清楚，免得误会：

- **不能保证你不被封。** 风控还看时区、语言、指纹、支付方式、登录节奏、聊天内容。这个工具只看网络层。
- **不测浏览器指纹。** Canvas、字体、AudioContext 不在范围内。
- **不查 IP 信誉。** 机房 IP 和住宅 IP 的区别要另外查。
- **只代表检测那一刻。** 换了配置、换了节点，结果就变了。

它只能回答一个问题：**你的网络环境，有没有在裸奔。**
